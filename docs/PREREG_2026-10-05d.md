The thread on Moltbook raised three replay mechanisms. They are kept apart, each with its own experiment:

| ID | Mechanism | State |
|---|---|---|
| K8 | no nonce store meant accept | fixed (`6ba76e6`) |
| K9 | the signed `time` is never checked, so there is no freshness | **this registration** |

K9 does **not** test persistence. Its marks live in memory, like the nonce set. It also does not touch key
issuance or ejection (open limits in the README).

## What the code does today (read, not run)

`make_manifest` writes `time` (default `time.time()`) into the manifest. `sign_manifest` hashes it into
`manifest_sha3_512`, so it is authenticated. `verify_dock` never reads it. So a genuine record that a verifier has
not seen before verifies whatever its age, for example a record captured from a dock with a different verifier.

## Design under test

A separate function, so `verify_dock`'s contract does not change in this experiment:

`check_fresh(manifest, key_fp, marks, now, max_skew=None) -> (ok, why)`

1. `time` must be an `int` or `float` (not `bool`) and finite; otherwise refuse as malformed.
2. If `max_skew` is set, refuse if `time > now + max_skew`.
3. Refuse if `key_fp in marks` and `time <= marks[key_fp]`.
4. Otherwise accept. The caller updates `marks[key_fp] = time` only after **all** checks pass, including the nonce.

The harness composes it with `verify_dock` in this order: integrity and signature, then nonce (no add), then
`check_fresh`, then commit nonce and mark. `now` is injected (fixed `T0 = 1_800_000_000.0`), with no wall clock.

Whether `verify_dock` should require marks (refuse without them, as K8 does for nonces) is a contract change.
That decision belongs to Chad and is not made here.

## Constants

`T0 = 1_800_000_000.0`; one key pair (ML-DSA-65); NumPy `default_rng(0)` for the shuffle; `N_ORDER = 1000`;
`N_AFTER = 100`; `MAX_SKEW = 5.0` s; stale age `3600` s; future offset `86400` s.

## Predictions

- **P1 (the hole exists at base).** A genuine record with `time = T0 − 3600`, presented to `verify_dock` with an
  empty nonce set, returns `(True, ...)`. This is a prediction of failure.
- **P2 (the mark refuses old and equal times).** With `marks = {fp: T0}`: `time = T0 − 3600` refused, `time = T0`
  refused, `time = T0 + 1` accepted with `marks[fp] == T0 + 1` afterwards. Refusal reasons name the mark.
- **P3 (cost: out-of-order delivery).** 1000 genuine records with times `T0 + 0.1·i`. In order, 1000 of 1000
  accept. Shuffled (seed 0), the accepted count equals the number of left-to-right maxima of the permutation,
  which the harness computes independently. It is ≤ 20 (the expected value for n = 1000 is H₁₀₀₀ ≈ 7.49). So the
  mark discards almost every out-of-order record. This is the stated price of the design, not a bug.
- **P4 (a future-dated record locks out the key).** Without `max_skew`: one genuine record at `T0 + 86400` is
  accepted, then `N_AFTER` legitimate records at `T0 + 1 … T0 + 100` are refused, 100 of 100. With
  `max_skew = 5`: the future record is refused, and 100 of 100 are accepted.
- **P5 (non-finite and non-numeric times).** A naive `time <= mark` check accepts `NaN`, because every comparison
  with NaN is false. The harness shows this on a bare comparison. `check_fresh` refuses `NaN`, `inf`, `"1"` and
  `True`, 4 of 4. If `canonical()` cannot serialise one of them, so that no signed record can carry it, the harness
  reports that row as UNREACHABLE. That does not count as a refusal; P5 then holds on the reachable rows only, and
  says so.
- **P6 (K8 and earlier behaviour unchanged).** `tests/run_tests.py` passes. A replay of the same record still
  returns K8's `"nonce already seen (replay)"`, because the nonce check runs before the time check. A refused stale
  record does not add its nonce to the set.
- **P7 (sabotage, `--sabotage`).** `check_fresh` always accepts. P2 must be REFUTED, with exit 1.

## Anti-vacuity

P1 shows the instrument reports an acceptance where one should not happen. P3's shuffled arm and P4's no-skew
arm are predicted refusals of legitimate records, so the instrument must be able to count losses, not only
blocks. P5's naive arm shows the check can be silently bypassed. P7 shows the harness can tell the mechanism from
its absence.

## Output and pinning

`scripts/k9_freshness.py` prints one HELD/REFUTED line per prediction, then `VERDICT n of 6 as registered (P7 is
--sabotage)` and a `DIGEST`. Raw output goes to `results/k9/run.txt`. `RECORDED` is pinned in a separate commit.
CI runs the harness and checks that `--sabotage` exits 1.

## Limits

Simulation only, one key, injected clock, no real clock skew or network. Self-designed and self-tested by Claude,
so not independent validation. NOT VALIDATED on the S25.

## Unrun door

- **D1.** Restart persistence: persist both the nonce set and the marks, then test a replay of a pre-restart
  record after a restart. This is the next registration and is not run here.
- **D2.** A sliding window (accept times in `(mark − W, mark]` once each, through the nonce set) instead of a strict
  mark. Prediction: it recovers most of P3's out-of-order loss, at the cost of keeping nonces for `W` seconds.
