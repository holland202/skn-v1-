2. **`docs/k8/run.txt` was regenerated once** to include that unregistered line. The registered lines and the
   digest (`1e63fef0…`) are identical to the first run's.
3. **Self-tested.** Claude (Opus 5.5, Anthropic) found the defect from an outside question, then registered,
   fixed, tested and wrote it up. No independent run.
4. **K8a was read from the code before registration, not run;** its pass shows that the harness reads the old code
   correctly, nothing more.
5. **One existing test changed:** `test_k2a_genuine_record_verifies` called `verify_dock` without a store and
   expected acceptance, which is the behaviour K8 removes. It now passes `set()`.

## What this shows

- **Before K8, a missing nonce store meant accept.** At `ee573a3`, the same genuine record verified twice with no
  store (K8a). The default argument was the fail-open path, and the live dashboard and the benchmark used it.
- **After K8, it means refuse,** with the reason "no nonce store: replay cannot be checked (fail closed)". With a
  store, nothing changed: first accept, then "nonce already seen (replay)".
- **Integrity reasons are unchanged** (K8c), because the store check comes after the digest, key and signature
  checks. **A refused record never adds its nonce to the store** (K8d), so a forged record carrying a genuine
  nonce cannot burn it.

## What it does not show

- The store is still caller-kept and in memory. A fresh `set()` per call (which the benchmark now does, labelled)
  or a restart forgets every nonce. The manifest `time` is still unchecked.
- fredoffrededison's first two questions remain open limits: no issuer or registry for keys (the verifier
  trusts whichever public key its caller passes), and no membership, revocation, expiry or rotation.

## Deviation, appended 2026-10-06: the sabotage exit code was overdetermined

Found while reviewing the CI sabotage steps, after the registered run. In the registered run K8e is REFUTED, so
`return 0 if all(v.values()) else 1` returned 1 under `--sabotage` whether or not the sabotage did anything: a
sabotage that disabled nothing would still have exited 1. The CI step "K8 sabotage must exit 1" therefore did not show
that the sabotage caused a failure. K8f is registered as "K8b must be REFUTED; exit 1"; the harness did not implement
that exactly.

Change (separate commit, `scripts/k8_nonce_store.py` and `.github/workflows/verify.yml` only; the registration and the
registered run are untouched):

- `--sabotage` now exits 1 only if K8b is REFUTED.
- New `--sabotage-noop`: the same patching path, with a wrapper that leaves the behaviour under test alone. K8b must
  hold, exit 0. It is a control, not a second sabotage assertion: its digest equals the registered digest.
- New CI step requiring `--sabotage-noop` to exit 0.
