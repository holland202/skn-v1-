## Open

- K3: feed the allocator's clipped output back into the pose update (the README's open experiment).
  **Found while preparing it:** every HET thruster points +0.3 in z, and HET commands are clipped to [0, 1]
  (they only push). So a −z command realizes nothing:
  `allocate([0,0,-1,0,0,0])` → B·u = [0, 0, 0] (with +z: [0, 0, 1]). Once the loop is closed through the
  actuators, a node cannot descend at all. Any K3 result has to face this first. It is either a design
  choice (a gravity-well lander?) or a missing thruster.
