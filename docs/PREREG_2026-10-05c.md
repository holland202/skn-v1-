## Finding (read from the code, not run, before this registration)

`skn.ccpl.verify_dock(record, public_key, seen_nonces=None)` checks the nonce only `if seen_nonces is not None`.
With the default, a genuine record verifies every time it is presented: replay protection is fail-open when the
store is missing. Three callers in this repository omit the store: `skn_orbital_tui.py` (`dock_ring`),
`scripts/bench_k1_k2.py`, and three refusal checks in `scripts/demo_30s.py` / `scripts/demo_visual.py`. The
README's limitation 9 says the store is caller-kept and in memory. It does not say that a missing store means
accept.

## K8: refuse when there is no nonce store

`verify_dock` keeps its integrity checks first and in the same order (digest, key fingerprint, signature), so a
tampered or wrong-key record is refused for the same reason as before. Then, if `seen_nonces is None`, it
returns `(False, "no nonce store: replay cannot be checked (fail closed)")`. Callers in this repository pass a
store.

**Predictions.**
- **K8a (defect, code at `ee573a3`, read with `git show`).** A genuine record verified twice with no store:
  `(True, True)`.
- **K8b (fix).** The same: both calls return False, with the reason "no nonce store: replay cannot be checked
  (fail closed)". With a store: the first call True, the second `(False, "nonce already seen (replay)")`
  (unchanged).
- **K8c (integrity reasons unchanged, no store passed).** Target changed with the digest recomputed: "signature
  does not verify". Another node's key: "record names a different public key". Missing field: starts with
  "malformed record".
- **K8d (refusals leave the store untouched).** With one shared store: a tampered record, a wrong-key record and a
  malformed record are each refused, the store is still empty afterwards, and then the genuine record
  verifies True. This guards against a forged record burning a genuine nonce.
- **K8e (callers).** No call to `verify_dock` in `skn/`, `scripts/` or `skn_orbital_tui.py` omits the store
  (static count of calls with fewer than three arguments: 0). `scripts/demo_30s.py` prints `DEMO PASS`. The
  dashboard test still counts 6 `sig VALID`.
- **K8f (sabotage, `--sabotage`).** The skip-when-missing branch is restored: K8b must be REFUTED; exit 1.

## What K8 does not do (stated before the code)

- The store is still a caller-kept, in-memory set. A caller that passes a fresh `set()` on every call has no
  replay protection, and a restart forgets every nonce. A persisted store is open.
- The manifest `time` is still unchecked (no freshness window).
- Fred's first two questions are not addressed: nothing issues or registers keys (each node makes its own at its
  first dock, and the verifier trusts whichever public key its caller passes), and there is no membership,
  revocation, expiry or rotation. These are recorded as open limits.

## Open (unrun)

- A persisted nonce store (e.g. beside the vault file) and a freshness window on `time`.
- A key registry with membership and revocation, and the test of whether an ejected node's key is refused.
